# Referral Program

The referral program rewards users who bring new participants to the platform. When a referred user pays platform fees, the referrer earns a percentage of those fees.

## How Referrals Work

```
User A (referrer) → refers → User B
                              ↓
User B pays fees (creation, buy, sell)
                              ↓
User A earns referral reward (% of fees)
```

### 1. Register a Referral

When a new user joins, they register their referrer via the `POST /registerReferral` endpoint:

**Request body:**
```json
{
  "userWallet": "0x...",
  "userId": "user_123",
  "referrerWallet": "0x...",
  "referrerId": "user_456"
}
```

**Rules:**
- A user can only register **one referrer** — cannot be changed
- Users **cannot refer themselves**
- Referral should be registered before any fee-generating activity

### 2. Fee Events That Generate Rewards

The system tracks **four types** of on-chain fee events:

| Event | Description | Fee Source |
|-------|-------------|------------|
| **RWA Creation** | Business deploys an RWA token | `createRWAFee` |
| **Pool Creation** | Business deploys a pool | `createPoolFeeRatio` |
| **Buy (mint)** | Participant buys RWA tokens | `entryFeePercent` |
| **Sell (burn)** | Participant sells RWA tokens | `exitFeePercent` |

When any of these events occur on-chain, the blockchain scanner picks them up and publishes to a message queue. The loyalty service processes each event:

1. Looks up the fee payer's wallet to find their referral record
2. Records the commission in the payer's fee history
3. If the payer has a referrer, calculates and records the referral reward

### 3. Referral Reward Calculation

The referral reward is a percentage of the commission amount:

```
rewardAmount = commissionAmount × referralRewardPercentage / 10000
```

The `referralRewardPercentage` is a protocol-level parameter configured in the loyalty service. The value is expressed in **basis points** (bps), where 10 000 bps = 100%. For example, a 10% referral reward rate equals 1 000 bps.

With a 10% referral reward rate and a 100 USDT commission:

```
rewardAmount = 100 × 1000 / 10000 = 10 USDT
```

Here, `1000` represents 10% (since 1000 bps = 10%), and dividing by `10000` converts basis points back to a decimal fraction.

## REST API Endpoints

| Endpoint | Description |
|----------|-------------|
| `POST /registerReferral` | Register a new referral relationship |
| `POST /getReferrals` | Get the list of users referred by a referrer |
| `POST /getFees` | Get aggregated fees and rewards for a user |
| `POST /getReferrerClaimHistory` | Get the full audit trail of referral rewards |
| `POST /createReferrerWithdrawTask` | Create a withdrawal request for accumulated rewards |
| `POST /getReferrerWithdraws` | Get the status and history of withdrawal requests |

## Withdrawing Rewards

Referral rewards are held in the **ReferralTreasury** smart contract. The withdrawal process involves several steps and validations.

### Creating a Withdrawal Request

Users initiate a withdrawal by calling `POST /createReferrerWithdrawTask` with:

```json
{
  "userWallet": "0x...",
  "userId": "user_123",
  "chainId": 1,
  "tokenAddress": "0x...",
  "amount": 100.50
}
```

### Validation Checks

Before processing, the system performs the following checks:

1. **Supported Network** — the `chainId` must be in the configured `supportedNetworks` list
2. **Cooldown Period** — at least **30 days** must have passed since the last withdrawal (`60 × 60 × 24 × 30` seconds)
3. **Sufficient Balance** — the requested amount must not exceed the available reward balance

### Multi-Signature Security

The **ReferralTreasury** contract requires **3 out of 5** authorized signers to approve any withdrawal. This multi-signature mechanism ensures that no single party can unilaterally withdraw funds.

### Processing Flow

```
User → POST /createReferrerWithdrawTask
                ↓
      Validate checks (network, cooldown, balance)
                ↓
      Generate message hash via ethers.solidityPackedKeccak256
      (userWallet, tokenAddress, amount, taskExpiredAt)
                ↓
      Create task in SignersManager (multi-signature coordination)
                ↓
      SignersManager collects 3 of 5 signatures
                ↓
      Task sent to Eden (external on-chain executor)
                ↓
      Eden executes ReferralTreasury.withdraw() on-chain
                ↓
      Withdrawal record created in referrerWithdraws collection
```

### Tracking Withdrawal Status

Users can track their withdrawal requests via `POST /getReferrerWithdraws`:

```json
{
  "filter": { "userWallet": "0x..." },
  "sort": { "createdAt": -1 },
  "limit": 10,
  "offset": 0
}
```

The response includes the `taskId` which can be used to track the task in Eden.

### Auditability

Every reward in the referrer claim history contains a `transactionHash` — the on-chain transaction hash that generated the reward. Anyone can verify that a recorded reward corresponds to a real on-chain transaction.
