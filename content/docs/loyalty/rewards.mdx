# Rewards & Withdrawals

Referral rewards are earned when your referred users perform on-chain operations (buy, sell, create RWA, create pool). The rewards are tracked in the loyalty service and can be withdrawn from the **ReferralTreasury** smart contract through a multi-signature approval process.

## How Rewards Accumulate

When a referred user performs an on-chain operation, the blockchain events daemon:

1. Finds the referral relationship for the payer
2. Records the commission in `commissionHistory`
3. If a referrer exists — calculates the reward: `reward = commission × referralRewardPercentage / 10000`
4. Records the reward in `referrerClaimHistory`
5. Updates aggregated data in `fees`

### Reward Formula

```
rewardAmount = commissionAmount × referralRewardPercentage / 10000
```

- `referralRewardPercentage` — protocol parameter in basis points (bps)
- Example: 10% = 1000 bps, commission 100 USDT → reward 10 USDT

## How the Treasury Works

The **ReferralTreasury** is a smart contract that holds USDT allocated for referral rewards. Key characteristics:

- **Manually funded** — the treasury is topped up manually by the protocol. There is no automatic minting. The total available reward pool is limited by what has been deposited
- **Multi-sig withdrawal** — every withdrawal requires signatures from authorized signers (same system as RWA and pool deployments)
- **Emergency withdrawal** — Governance can withdraw tokens in case of emergency

## Withdrawal Flow

```
1. Create Withdraw Task (off-chain)
2. Signers Review and Sign (off-chain)
3. Execute On-Chain (anyone can execute)
```

### Step 1: Create a Withdraw Task

**`POST /createReferrerWithdrawTask`**

Request body:

```json
{
  "chainId": 1,
  "tokenAddress": "0xdAC17F958D2ee523a2206206994597C13D831ec7",
  "amount": "50000000"
}
```

The system validates:

1. **Supported network** — `chainId` must be in the `supportedNetworks` list
2. **Cooldown** — at least **30 days** must have passed since the last withdrawal (`taskCooldown`)
3. **Available balance** — requested amount must not exceed `referralRewardAmount - totalWithdrawnAmount`
4. **Generates a message hash** — via `ethers.solidityPackedKeccak256(userWallet, tokenAddress, amount, taskExpiredAt)`
5. **Creates a signature task** — via the Signers Manager
6. **Returns task details**

Response:

```json
{
  "id": "...",
  "userWallet": "0xYourWallet...",
  "chainId": 1,
  "tokenAddress": "0xdAC17F958D2ee523a2206206994597C13D831ec7",
  "amount": "50000000",
  "taskId": "sig_task_456",
  "taskExpiredAt": 1712345678,
  "taskCooldown": 1714937678,
  "totalWithdrawnAmount": "50000000",
  "createdAt": "2025-01-01T00:00:00.000Z",
  "updatedAt": "2025-01-01T00:00:00.000Z"
}
```

### Step 2: Signers Approve

The Signers Manager distributes the task to authorized signers. Each signer reviews the withdrawal and signs the message hash. Once enough signatures are collected (minimum **3 out of 5**), the task is marked as completed.

The message that signers sign follows the **EIP-712** typed data standard:

```solidity
struct WithdrawRequest {
    address token;
    uint256 amount;
    uint256 deadline;
}

// EIP-712 Domain
// { name: "ReferralTreasury", version: "1", chainId: 1, verifyingContract: "0x..." }
```

Each signer produces a signature over the typed data, resulting in a 65-byte `(r, s, v)` signature:

```
0xabc123...def45678901234567890123456789012345678901234567890123456789012345678901b
```

### Step 3: Execute On-Chain

Once the signatures are collected, anyone can call `ReferralTreasury.withdraw()` on-chain:

```solidity
function withdraw(
    address token,          // USDT address
    uint256 amount,         // Amount to withdraw
    uint256 deadline,       // Task expiration timestamp
    address[] calldata signers,    // Signer addresses
    bytes[] calldata signatures    // Collected signatures
) external
```

The contract verifies:

- The request hasn't expired (10-minute window)
- Each signer is authorized in AddressBook
- Each signature is valid for the withdrawal parameters
- No duplicate signatures

After successful withdrawal, the tokens are transferred to your wallet and a `ReferralTreasury_Withdrawn` event is emitted.

## End-to-End Example: Withdrawing 50 USDT

Suppose you have accumulated **100 USDT** in referral rewards and want to withdraw **50 USDT**.

**Step 1 — Create the task:**

Call `POST /createReferrerWithdrawTask` with:

```json
{
  "chainId": 1,
  "tokenAddress": "0xdAC17F958D2ee523a2206206994597C13D831ec7",
  "amount": "50000000"
}
```

The system checks:

- ✅ Available rewards: 100 USDT ≥ 50 USDT
- ✅ Cooldown passed (no previous withdrawal in the last month)
- ✅ Generates a message hash and creates a signature task

**Step 2 — Signers approve:**

Three authorized signers review the withdrawal parameters and each signs the EIP-712 typed data. The collected signatures array looks like:

```json
[
  "0xabc123...01b",  // Signer 1 signature
  "0xdef456...02c",  // Signer 2 signature
  "0xghi789...03d"   // Signer 3 signature
]
```

**Step 3 — Execute on-chain:**

Call `ReferralTreasury.withdraw()` with:

- `token`: `0xdAC17F958D2ee523a2206206994597C13D831ec7`
- `amount`: `50000000`
- `deadline`: `1712345678`
- `signers`: `[0xSigner1..., 0xSigner2..., 0xSigner3...]`
- `signatures`: `[0xabc123...01b, 0xdef456...02c, 0xghi789...03d]`

The contract verifies all signatures, transfers **50 USDT** to your wallet, and emits `ReferralTreasury_Withdrawn`.

## Constraints

| Constraint | Value | Description |
|---|---|---|
| Task expiry | **10 minutes** | The signature task expires if not executed in time |
| Cooldown | **30 days** | Must wait 30 days between withdrawal tasks |
| Min signers | **3 out of 5** | Minimum number of signatures required |
| Available amount | `referralRewardAmount - totalWithdrawnAmount` | Cannot withdraw more than earned |

## Viewing Withdrawals

- **`POST /getReferrerWithdraws`** — view your withdrawal history with amounts and task IDs
- **`POST /getReferrerClaimHistory`** — view on-chain withdrawal events (ReferralTreasury_Withdrawn)
- **`POST /getFees`** — view your accumulated referral rewards (`referralRewardAmount`)

## Auditing

Each reward in `referrerClaimHistory` contains a `transactionHash` — the on-chain hash of the event that generated the reward. This allows anyone to verify that the recorded reward corresponds to a real on-chain transaction.

Each withdrawal task contains a `taskId` that can be used to track the task status in Eden.

## Emergency

If there's an issue with the treasury, Governance can call `emergencyWithdraw()` to transfer tokens to any address without multi-signature approval.
