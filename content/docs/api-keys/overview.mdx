# API Keys

> **⚠️ В разработке** — API Keys как отдельный механизм аутентификации ещё не реализованы в бэкенде. Текущая реализация использует wallet-based JWT-аутентификацию (см. ниже).

## Текущая реализация: Wallet-based JWT

На данный момент аутентификация в API осуществляется через **подпись сообщения (EIP-712) кошельком пользователя** с последующей выдачей JWT-токенов. Это основной и единственный способ аутентификации.

### Как это работает

1. Пользователь подписывает сообщение своим кошельком (EIP-712 типизированные данные)
2. Сервер проверяет подпись и возвращает пару токенов: **accessToken** (краткосрочный) и **refreshToken** (долгосрочный)
3. AccessToken используется для аутентификации GraphQL-запросов
4. RefreshToken используется для получения нового accessToken по истечении срока действия

### GraphQL-операции аутентификации

| Операция | Тип | Описание |
|---|---|---|
| [`authenticate`](/docs/api/auth/authenticate) | Mutation | Подпись кошельком → получение JWT-токенов |
| [`refreshToken`](/docs/api/auth/refresh-token) | Mutation | Обновление accessToken по refreshToken |
| [`revokeTokens`](/docs/api/auth/revoke-tokens) | Mutation | Отзыв refreshToken'ов |
| [`getUserTokens`](/docs/api/auth/get-user-tokens) | Query | Получение списка активных refreshToken'ов |

### REST-эндпоинты (альтернативный доступ)

| Эндпоинт | Метод | Описание |
|---|---|---|
| `/authenticate` | POST | Аутентификация по подписи кошелька |
| `/refreshToken` | POST | Обновление токенов |
| `/getUser` | POST | Получение данных пользователя |
| `/getUserTokens` | POST | Список токенов пользователя |
| `/revokeTokens` | POST | Отзыв токенов |

### Использование

```bash
curl -X POST https://api.slices.xyz/graphql \
  -H "Authorization: Bearer <accessToken>" \
  -H "Content-Type: application/json" \
  -d '{"query": "{ getBusinesses(input: { filter: {} }) { id name } }"}'
```

## Планируемое: API Keys

API Keys будут предоставлять альтернативу wallet-signature аутентификации для автоматизированных интеграций, ботов и AI-агентов, которым нужен постоянный доступ без интерактивного подписания кошельком.

**Планируемые операции:**

- `createApiKey` — создание ключа
- `updateApiKey` — переименование ключа
- `deleteApiKey` — удаление/отзыв ключа
- `getApiKeys` — список всех ключей
- `getApiKey` — получение одного ключа

Следите за обновлениями — функциональность появится в одном из следующих релизов.
