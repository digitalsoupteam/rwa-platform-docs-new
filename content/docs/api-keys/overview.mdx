# API Keys

> **⚠️ Under development** — API Keys as a separate authentication mechanism are not implemented in the backend yet. The current implementation uses wallet-based JWT authentication (see below).

## Current implementation: Wallet-based JWT

Currently, API authentication is performed via **message signature (EIP-712) by the user's wallet**, followed by the issuance of JWT tokens. This is the primary and only authentication method.

### How it works

1. The user signs a message with their wallet (EIP-712 typed data)
2. The server verifies the signature and returns a pair of tokens: **accessToken** (short-lived) and **refreshToken** (long-lived)
3. The accessToken is used to authenticate GraphQL requests
4. The refreshToken is used to obtain a new accessToken once the current one expires

### GraphQL authentication operations

| Operation | Type | Description |
|---|---|---|
| [`authenticate`](/docs/api/auth/authenticate) | Mutation | Wallet signature → obtaining JWT tokens |
| [`refreshToken`](/docs/api/auth/refresh-token) | Mutation | Refreshing accessToken via refreshToken |
| [`revokeTokens`](/docs/api/auth/revoke-tokens) | Mutation | Revoking refreshTokens |
| [`getUserTokens`](/docs/api/auth/get-user-tokens) | Query | Retrieving the list of active refreshTokens |

### REST endpoints (alternative access)

| Endpoint | Method | Description |
|---|---|---|
| `/authenticate` | POST | Authentication via wallet signature |
| `/refreshToken` | POST | Refreshing tokens |
| `/getUser` | POST | Retrieving user data |
| `/getUserTokens` | POST | List of the user's tokens |
| `/revokeTokens` | POST | Revoking tokens |

### Usage

```bash
curl -X POST https://api.slices.xyz/graphql \
  -H "Authorization: Bearer <accessToken>" \
  -H "Content-Type: application/json" \
  -d '{"query": "{ getBusinesses(input: { filter: {} }) { id name } }"}'
```

## Planned: API Keys

API Keys will provide an alternative to wallet-signature authentication for automated integrations, bots, and AI agents that need persistent access without interactive wallet signing.

**Planned operations:**

- `createApiKey` — create a key
- `updateApiKey` — rename a key
- `deleteApiKey` — delete/revoke a key
- `getApiKeys` — list all keys
- `getApiKey` — retrieve a single key

Stay tuned for updates — this functionality will appear in one of the upcoming releases.
