# AI Overview

The Slices platform provides two distinct AI capabilities: **AI Assistant** — a conversational chat-bot for user support, and **AI Evaluator** — a synchronous risk scoring engine for businesses and pools.

Both capabilities are powered by **OpenRouter** — a unified API gateway that provides access to multiple LLM providers through a single interface. OpenRouter handles request routing, fallback logic, and generation metadata tracking.

---

## AI Assistant

A conversational chat-bot that helps users interact with the platform. Each user can create multiple assistants with custom names and optional system prompts.

### Architecture

```
User → AI Assistant Service → OpenRouter API → LLM → Response
```

The AI Assistant service:
1. Receives a user message
2. Loads the assistant's configuration (name, optional system prompt)
3. Retrieves the last 5 messages from conversation history for context
4. Sends the conversation to OpenRouter's `/chat/completions` endpoint
5. Returns the AI response to the user

### Model

Default model: **`google/gemini-2.0-flash-001`** (configurable via `OPENROUTER_MODEL` environment variable). The model can be overridden per-request.

### Context

Each assistant has an optional **`systemPrompt`** field — a plain text instruction that sets the assistant's behaviour. No dynamic data injection or pre-defined context modes are used. If no system prompt is provided, only the assistant's name is used as context.

### Limits

| Limit | Value | Behaviour |
|---|---|---|
| Assistants per user | **10** | Returns `409 Conflict` when exceeded |
| Message length | **4096 characters** | Returns `413 Payload Too Large` when exceeded |
| Conversation history | **Last 5 messages** | Sent as context to the LLM |
| Message retention | **30 days** | Older messages are automatically pruned |
| Max stored messages | **100** per assistant | Oldest messages are pruned when exceeded |

### API Endpoints

All endpoints use `POST` method:

| Endpoint | Description |
|---|---|
| `/createAssistant` | Create a new assistant |
| `/updateAssistant` | Update assistant name or system prompt |
| `/deleteAssistant` | Delete an assistant |
| `/getAssistant` | Get assistant by ID |
| `/getUserAssistants` | List all assistants for the current user |
| `/createMessage` | Send a message and receive AI response |
| `/getMessageHistory` | Get message history for an assistant |
| `/getMessage` | Get a specific message by ID |
| `/updateMessage` | Update a message |
| `/deleteMessage` | Delete a message |

### Error Codes

| Code | Description |
|---|---|
| `400` | Bad request (invalid input) |
| `401` | Unauthorized |
| `404` | Assistant or message not found |
| `409` | Assistant limit exceeded |
| `413` | Message too long |
| `429` | Rate limited |
| `500` | Internal server error |

## AI Evaluator

A synchronous risk scoring engine embedded in the RWA service. When a business or pool is created or updated, the system can trigger an AI-based risk assessment.

### Architecture

```
Client → RWA Service → OpenRouter API → LLM → Risk Score (1-100)
```

The evaluation is **synchronous** — the RWA service calls OpenRouter's `/chat/completions` endpoint with a structured prompt that includes business/pool details and a list of risk factors. The LLM responds with a numeric score (1-100) and a brief reasoning text.

### Usage

- **Business risk score** — triggered via `updateBusinessRiskScore` mutation (GraphQL) or `/updateBusinessRiskScore` endpoint
- **Pool risk score** — triggered via `updatePoolRiskScore` mutation (GraphQL) or `/updatePoolRiskScore` endpoint

### Risk Factors

The AI evaluates the following factors:
- Business/pool model viability
- Market competition and conditions
- Regulatory compliance risks
- Financial stability indicators
- Operational risks and scalability
- Management team experience
- Industry-specific challenges
- Market positioning and branding
- Technology and innovation potential
- Target market size and accessibility

### Response Format

```
RISK_SCORE: 45
REASONING: Moderate risk due to competitive market, but strong business model and experienced team
```

## OpenRouter

Both AI features use **OpenRouter** as their LLM gateway. OpenRouter provides:

- **Unified API** — single endpoint (`/chat/completions`) for multiple models
- **Model flexibility** — model is configurable via environment variable (`OPENROUTER_MODEL`)
- **Generation metadata** — track token usage, generation IDs, and model info
- **Middle-out compression** — AI Assistant uses this transform to handle large conversation contexts efficiently

Configuration:

| Variable | Default | Description |
|---|---|---|
| `OPENROUTER_BASE_URL` | `https://openrouter.ai/api/v1` | OpenRouter API endpoint |
| `OPENROUTER_API_KEY` | — | API key for authentication |
| `OPENROUTER_MODEL` | `google/gemini-2.0-flash-001` | Default model for completions |
